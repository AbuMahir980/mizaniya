What may move, and what may not
transform: translateY and box-shadow. No scaling — a component that grows on hover is a component shown at a size it is not. No rotation change — the slant is the stack's geometry, not a reaction. The hero never tilts at all, because it carries the figure the page is about and a crooked money figure is a money figure set crooked. 180ms in, 180ms out, cubic-bezier(.2,0,0,1).
@media (hover: hover) {
  .stack > *:hover { transform: translateY(-14px) }
  .stack > *:hover ~ * { transform: translateY(88px) }
}
@media (prefers-reduced-motion: reduce) {
  .stack > * { transition: box-shadow 180ms }
  .stack > *:hover { transform: none }
}

Proof — the same rule, one object rather than five floating cards
The first version left 56px between every card on a 1140 column, and cards with holes around them read as scattered rather than composed. Half the gap, and the arrangement sits inside its own bordered panel so it has an edge. Hover lifts a single component by 8px — smaller than the cascade's, because nothing is being uncovered, only pointed at.
Keyboard: each component is focusable and :focus-visible produces the identical lift plus the ring from tokens.md §5 — motion.md §6, hover is never the only signal. Tab order follows the reading order of the quincunx: the two above, then the middle, then the two below.
Hover reveals nothing. That is the whole constraint, and it is motion.md §5 inherited by §9 — the page must read completely with motion off, and a touch device has no pointer at all. So every card in the cascade already shows its own label and figure at rest; hovering gives you the rest of a card you could already identify, never the identity of one you could not. motion.base 180ms, the standard curve, transform and box-shadow only. Under prefers-reduced-motion the lift is dropped and the shadow alone changes — §5's rule read literally: remove movement, keep colour, never remove information.
